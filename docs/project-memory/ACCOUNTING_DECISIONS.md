# Tomorrow Finance — Approved Accounting Decisions
Updated: 2026-11-11. This is a policy record, not authorization to enable dormant posting.

1. **Balance authority:** a transaction affects its account once using the actual amount debited/credited in that account's currency. Never count the same economic event twice.
2. **Cross-currency:** user enters original amount/currency; application may suggest account-currency amount using the historical transaction-date FX rate; user may correct to the bank's actual amount before save. Preserve original amount, original currency, historical/actual conversion information and account-currency amount. Current market valuation is separate from historical transaction value.
3. **Refund:** credit only the actual amount returned by the bank. Preserve refund amount/currency and actual conversion; FX difference is a separate analytics figure, not another balance entry. Attribute operating refunds appropriately to the original expense category, including across periods when supported.
4. **Credit cards:** credit limit is neither asset nor liability by itself. Purchases/cash withdrawals create negative balance/debt and reduce net worth once. Paying a credit card from another account is a settlement/transfer, not a new operating expense; no double counting.
5. **Loans:** net worth deducts remaining *original principal*, not future contractual interest. Contractual remaining installments are displayed separately. Principal reduction for a repayment = payment amount × (original principal / contractual total), under the approved loan policy. Late fees do not reduce principal. Remaining installment count uses ceil(remaining contractual / installment). Closing without payment removes loan from net worth but preserves history.
6. **Debts, receivables, payables and cheques:** schedules or due dates do not automatically debit or credit accounts. Actual confirmed payment/receipt, linked to the selected account and date, changes balance once.
7. **Installments:** schedule-only implementation remains; no automatic due-date posting. Any payment posting requires explicit user confirmation and an approved safe implementation.
8. **Transfers:** internal transfers and credit-card payments are not operating income/expense. Cross-currency source/destination actual amounts must reconcile; transfer fees must be accounted for separately and consistently.
9. **Money precision:** validate supported currencies and their decimal scales; use safe integer minor units for aggregation, reject invalid precision/overflow; Arabic/Persian numerals supported in input parsing. Supported currencies: EGP USD EUR GBP SAR AED QAR (2 decimals); OMR KWD JOD (3 decimals). Unsupported JPY must not silently fall back to 2 decimals.
10. **Historical reports:** no invented opening balance. An account history report requires a verified openingBalanceDate and complete movements. Missing/ambiguous data returns historical_data_unavailable/null amounts with reason.
11. **Posting safety:** postingAllowed=false; dormant V3 journal and recovery safeguards remain blocked until separately tested, approved and explicitly activated.
